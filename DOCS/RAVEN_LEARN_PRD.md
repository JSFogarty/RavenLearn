# Raven Learn — Product Requirements Document

## 1. Product Vision

**Raven Learn** is a beautiful stock-trade learning app that feels like sitting beside a professional trader who pauses the chart and explains what is happening.

The app is not a trading bot, not a broker, and not a paper-trading simulator in version 1. It is a chart-learning cockpit that helps users understand price action, volume, trend, patterns, Wyckoff context, moving averages, and setup quality.

The app should make chart reading feel visual, guided, and understandable.

## 2. Core Positioning

Raven Learn helps users answer:

- What is happening on this chart?
- Why might it be happening?
- What chart evidence supports that idea?
- What would confirm or invalidate the setup?
- Is this stock active enough and affordable enough to study or trade?

## 3. MVP Product Promise

The first version should deliver this experience:

> A user opens Raven Learn, finds active stocks within their price range, opens a TradingView-style chart, sees key chart structures highlighted directly on the chart, and receives a clear AI explanation of what the chart is showing.

## 4. Non-Goals for Version 1

Do not build these in v1:

- Broker connection
- Real trading
- Paper trading
- Options chain
- Options strategy builder
- Automated trade execution
- Complex portfolio tracking
- Multi-agent Raven trading committee
- Full backtesting engine
- Social features
- Paid subscription billing

These can be future phases after the learning experience is excellent.

## 5. Target User

The first target user is a beginner-to-intermediate trader who:

- Wants to learn chart reading visually
- Has a small account or limited capital
- Needs stocks filtered by realistic price range
- Wants explanations, not just indicator overlays
- Wants to understand why patterns may matter
- Wants a guided learning experience without being pushed into trades

## 6. Core User Flow

1. User opens Raven Learn.
2. App loads the dashboard.
3. User selects a price range, volume/activity filters, and watchlist/screener criteria.
4. Screener returns active stocks that fit the user’s filters.
5. User opens a ticker.
6. TradingView-style chart loads with drawing tools.
7. App overlays key chart callouts such as support/resistance, trend, moving averages, volume events, breakout zones, or possible Wyckoff phase.
8. User clicks **Explain Chart**.
9. AI Coach explains what is happening in plain English.
10. User can save notes to the ticker/session.
11. Journal/progress tracker confirms which product requirements are complete during development.

## 7. Data Sources

### 7.1 Massive.com API

Use Massive.com API for:

- Current or recent market data
- Ticker snapshots
- Aggregates/candles
- Screener inputs where available
- Volume and price activity
- Stock metadata where available

### 7.2 Massive.com Flat Files

Use Massive.com flat files for:

- Historical candle data
- Longer-term indicator calculations
- Local cached analysis
- Future backtesting or historical learning mode

### 7.3 OpenAI API

Use OpenAI API for:

- Plain-English chart explanation
- Learning-style breakdowns
- “Why this matters” explanations
- Confirmation/invalidation explanations
- Pattern education
- User Q&A about the current chart

Important: AI should explain structured data generated by the app. It should not hallucinate from vague prompts.

Preferred analysis pipeline:

```text
Massive data → normalized candles → indicators → rule engine → structured chart summary → OpenAI explanation → chart annotations + AI Coach panel
```

## 8. Primary App Areas

## 8.1 Dashboard

The dashboard should include:

- App name: Raven Learn
- Main navigation
- Watchlist
- Screener preview
- Recently viewed tickers
- Saved notes
- Learning progress or recent chart reviews

## 8.2 Screener

The screener must help users find active, realistic stocks.

Required screener filters:

- Minimum price
- Maximum price
- Minimum volume
- Relative volume if available/calculable
- Percent change
- Gap up/down
- Above/below moving averages
- Near high of day
- Near low of day
- Breakout candidate
- Pullback candidate
- Trend direction

Important requirement:

The screener must avoid returning stocks that are unrealistic for the user’s account size when the user sets a price range. For example, if the user has $50, the app should not suggest extremely expensive stocks like BRK-A unless the user explicitly removes the filter.

Suggested default beginner/small-account filters:

- Price: $2 to $50
- Minimum average volume: 500,000 shares
- Relative volume: above 1.5 if available
- Spread/liquidity warning if data allows

Screener result columns:

- Symbol
- Company name
- Price
- Percent change
- Volume
- Relative volume
- Trend label
- Pattern candidate
- Setup Quality Score
- Reason it appeared

## 8.3 Chart Workspace

The chart workspace is the heart of the app.

Required:

- TradingView-style chart experience
- Candlestick chart
- Multiple timeframes
- Drawing tools
- Watchlist/ticker selector
- Indicator controls
- Fullscreen mode
- Dark theme first
- Responsive layout for desktop first

Preferred implementation:

- TradingView Charting Library / Advanced Charts if access allows
- If not available, start with a custom chart using a web charting library and add drawing tools gradually

Required indicators for v1:

- Volume
- 20 moving average
- 50 moving average
- 200 moving average
- VWAP if available or calculable

Later indicators:

- RSI
- MACD
- MFI
- Bollinger Bands
- ATR

## 8.4 Chart Callouts and Highlights

When the app identifies a pattern, phase, signal, or important structure, it must be clearly highlighted on the chart.

Required highlight types:

- Support zone
- Resistance zone
- Trendline
- Breakout level
- Pullback area
- Volume spike marker
- Moving average reclaim/loss
- Higher high / higher low labels
- Lower high / lower low labels
- Possible Wyckoff phase range box
- Pattern boundary lines
- Setup score badge

Each chart callout should include:

- Label
- Confidence or clarity level
- Short reason
- Related candle range/time window
- Link to AI explanation panel section

Language rule:

Use cautious educational language such as:

- “Possible bull flag”
- “Potential accumulation range”
- “This may indicate…”
- “This would need confirmation…”

Avoid absolute language such as:

- “This will break out”
- “Buy here”
- “Guaranteed move”

## 8.5 AI Coach Panel

The AI Coach panel should explain the chart in plain English.

Required sections:

1. Current Read
2. Trend
3. Volume
4. Key Levels
5. Pattern Candidate
6. Wyckoff Context, if detected
7. Moving Averages
8. What Supports This Read
9. What Would Confirm It
10. What Would Invalidate It
11. Beginner Explanation
12. Risk/Education Note

Example tone:

> Price is currently holding above the 20 MA while moving sideways after a strong move up. That can sometimes mean buyers are still defending the trend, but the chart needs confirmation before assuming continuation.

AI Coach must not provide direct financial advice. It should educate, explain, and identify conditions.

## 8.6 Pattern Detection

Start with a small reliable list.

Phase 1 pattern candidates:

- Uptrend
- Downtrend
- Range/consolidation
- Breakout attempt
- Pullback
- Bull flag candidate
- Bear flag candidate
- Double top candidate
- Double bottom candidate
- Support/resistance test
- Moving average reclaim
- Moving average rejection

Phase 2 pattern candidates:

- Head and shoulders
- Inverse head and shoulders
- Cup and handle
- Wedge
- Triangle
- Gap and go
- Failed breakout
- Trend exhaustion

## 8.7 Wyckoff Learning Mode

Wyckoff should be educational and cautious.

Phase 1 Wyckoff callouts:

- Possible accumulation
- Possible distribution
- Selling climax candidate
- Buying climax candidate
- Spring candidate
- Upthrust candidate
- Test candidate
- Sign of strength candidate
- Sign of weakness candidate
- Markup
- Markdown

Required Wyckoff output:

- Highlight suspected range on chart
- Label possible phase
- Explain why the app is calling it out
- Explain what would confirm or reject the interpretation
- Include a beginner-friendly explanation

## 8.8 Setup Quality Score

The score should be educational, not a buy/sell signal.

Suggested name:

**Setup Quality Score**

Suggested score categories:

- Trend: 0–20
- Volume/activity: 0–20
- Structure/pattern clarity: 0–20
- Location/risk clarity: 0–20
- Confirmation: 0–20

Total: 0–100

The score must always show its breakdown and reasoning.

Example:

```text
Setup Quality: 72 / 100
Trend: 18 / 20 — price is above rising short-term averages.
Volume: 14 / 20 — volume increased on the breakout attempt.
Structure: 15 / 20 — consolidation is visible but not perfectly clean.
Location: 12 / 20 — price is near resistance, so risk/reward may be less ideal.
Confirmation: 13 / 20 — needs a clean close above resistance.
```

## 8.9 Notes and Learning Journal Inside App

Users should be able to save notes per ticker/chart session.

Required note fields:

- Symbol
- Timeframe
- Date/time
- User note
- AI chart explanation snapshot
- Setup score snapshot
- Pattern labels active at the time
- Screenshot or chart-state reference if available

This is separate from the development journal.

## 13. Definition of Done

Raven Learn v1 is done when:

- The PRD exists and is used as the source of truth
- The development journal tracks all completed actions
- Every Phase 0–11 requirement is marked complete, deferred, or intentionally removed
- Screener finds active stocks within user-defined price ranges
- Chart workspace loads real market data
- Drawing tools are available or an accepted fallback is documented
- Patterns/phases are visibly highlighted on the chart
- AI Coach explains what is happening and why
- Setup Quality Score is visible and explained
- User can save learning notes
- The app is beautiful enough to feel like a polished product, not a rough tool
